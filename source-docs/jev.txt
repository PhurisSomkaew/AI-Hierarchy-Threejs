[ Jev / System One Model ]
- เปิดตัว 15 ก.ย. 2026 โดย TypeSafe AI (SF, seed $40M, CEO: Diogo Almeida อดีต OpenAI หนึ่งในผู้ร่วมคิด RLHF)
- นิยามของบริษัทเอง : "a frontier-intelligence function call — unstructured state in, typed probabilistic decisions out"
- แปลไทย : ยัด "สภาพงานตอนนี้" เข้าไป แล้วได้ "การตัดสินใจที่มีชนิดข้อมูลกำกับ + ความน่าจะเป็น" ออกมา
- สำคัญ : มันไม่พ่นข้อความออกมาเลย -> ไม่ใช่ LLM

[ ชื่อ "System One" มาจากไหน ]
- มาจาก Kahneman ที่แบ่งการคิดของคนเป็น 2 ระบบ
  System 1 = คิดเร็ว อัตโนมัติ ไม่ต้องใคร่ครวญ  (เห็นไฟแดง -> เหยียบเบรก)
  System 2 = คิดช้า ใคร่ครวญ เป็นขั้นตอน        (คำนวณภาษีทั้งปี)
- LLM + Reasoning Model ที่เราใช้กันอยู่ = System 2
- Jev = ตัวแรกที่ถูกสร้างมาเป็น System 1 โดยเฉพาะ

--------------------------------------------------------------------------------
[ ประเด็นหลักของชั้น 5 : Transformer ไม่ได้มีไว้ทายคำอย่างเดียว ]

ความเข้าใจผิดที่คนมักติดไป :  Transformer = LLM = ตัวทายคำ   << ผิด
ความจริง :                  Transformer = สถาปัตยกรรม ที่เอาไปทำอะไรก็ได้

              [ Transformer ]   <-- แกนกลาง เหมือนกันทั้งคู่
                     |
         +-----------+-----------+
         |                       |
  [ Decoder ]            [ Parallel Sampler ]
  ทายทีละ token           ตอบทุกคำถามพร้อมกัน
  ต่อกันเป็นประโยค          จบใน pass เดียว
         |                       |
         v                       v
       LLM                     Jev
  "พ่นคำ"                  "ชี้คำตอบ"

=> เครื่องยนต์ตัวเดียวกัน คนละหัวจ่าย
=> และถ้าเปลี่ยนหัวจ่ายเป็นอย่างอื่นได้อีก ก็จะมี Model ประเภทใหม่เกิดขึ้นได้อีก

** ข้อควรระวังตอนสอน : RLCD ไม่ใช่ "สมองอีกแบบ" มันคือ "วิธีเทรน"
   Jev ก็เป็น Neural Network เหมือน LLM ทุกประการ **

--------------------------------------------------------------------------------
[ ทำไม Jev ถึง Hallucinate ไม่ได้ ]
- ไม่ใช่เพราะมันฉลาดกว่า หรือซื่อสัตย์กว่า
- แต่เพราะ "เราไม่ได้ให้ปากมันไว้" -> มันเลือกได้แค่จากลิสต์ที่เราเขียนไว้ล่วงหน้าเท่านั้น
- จะแต่งเรื่องก็ไม่มีที่ให้แต่ง และจะคืน type ผิดก็ไม่ได้

  LLM :  ถาม -> [ เลือกคำไหนก็ได้ในภาษา ]  -> มีช่องให้มั่ว
  Jev :  ถาม -> [ เลือกได้แค่ A / B / C ]  -> ไม่มีช่องให้มั่ว

[ แลกมาด้วยอะไร ] : มันตอบได้เฉพาะคำถามที่เราตั้งตัวเลือกไว้แล้ว
                   เจอเรื่องนอกลิสต์ = ตอบไม่ได้ ไม่ใช่ตอบมั่ว

--------------------------------------------------------------------------------
[ Calibration : ของที่ Jev มี แล้ว LLM ไม่มี ]

- LLM ก็มีความน่าจะเป็นนะ แต่มันคือ prob ของ "token ถัดไป" ไม่ใช่ prob ว่า "คำตอบนี้ถูก"
  -> LLM เลยพูดเต็มปากว่ามั่นใจมาก ทั้งที่ผิด  (calibration แย่)

- RLCD = Reinforcement Learning for Calibrated Decisions
  เทรนโดย optimize ตรงที่ "ความมั่นใจต้องตรงกับความถูกจริง"
  -> Jev บอก 90% แปลว่าใน 100 ครั้ง มันถูกจริงราว 90 ครั้ง

=> นี่คือหัวใจ : ตัวเลขมันเชื่อได้ ซอฟต์แวร์เลยเอาไปเขียน if ต่อได้ทันที
   ซึ่ง output ของ LLM ทำแบบนี้ไม่ได้

--------------------------------------------------------------------------------
[ Jev ตอบได้แค่ 3 แบบ ]

  Bool    -> ใช่ / ไม่ใช่  พร้อม % ความมั่นใจ      "ตั๋วใบนี้ด่วนไหม" -> ด่วน 99.9%
  Choice  -> เลือก 1 จากลิสต์ พร้อม prob ทุกตัว    "ส่งให้ทีมไหน" -> Support 0.7 / Billing 0.2 / Dev 0.1
  Score   -> ให้คะแนนบนสเกลที่เรานิยาม             "งานนี้ยากแค่ไหน" -> low / medium / high

- วิธีเรียกใช้ : ส่ง "state" (ข้อมูลตอนนี้) + "ลิสต์คำถามที่มี type" เข้าไป
  ได้กลับมา 1 คำตอบต่อ 1 คำถาม ทั้งหมดใน pass เดียว

--------------------------------------------------------------------------------
[ ประเด็นหลักของชั้น 6 : เอาไปใช้คู่กับ Agentic ยังไง ]

ปัญหาของ Agentic ที่เรียนมาในชั้น 6 :
  "Agentic วิเคราะห์ผ่าน LLM ว่าควรหาข้อมูลจากไหน -> LLM วิเคราะห์ว่าควร Action อะไร ไปทางไหน"
  => ทุกลูกศรเรียก LLM หมด -> ช้า + แพง + คำตอบเป็นข้อความที่เอาไปเขียน if ต่อไม่ได้

Jev เสียบเข้าไปได้ครบทั้ง 4 Design Patterns :

  1 Reflection  ->  "Outcome นี้ผ่านไหม"        ->  Bool
  2 Planning    ->  "แผนชุดนี้ดีพอหรือยัง"        ->  Score
  3 Tool Use    ->  "งานนี้ใช้ tool ไหน"         ->  Choice
  4 MultiAgent  ->  "ส่งให้ agent ตัวไหน"        ->  Choice

** Jev ไม่ได้มาแทน 4 patterns นี้ -- มันมาเป็นเครื่องยนต์ที่ทำ 4 อย่างนี้ให้เร็วขึ้น **

[ แบ่งหน้าที่กัน 3 ตัว ]
  Jev   = ตัดสินใจว่าจะไปทางไหน   (ไฟจราจร)
  LLM   = คิด เขียน วิเคราะห์      (สมอง)
  Agent = ลงมือทำงานจริง          (มือ)

[ ตัวอย่าง ]
  "2+2 เท่ากับเท่าไหร่"          -> Jev : งานง่าย ส่งโมเดลเล็กพอ
  "วิเคราะห์ธุรกิจนี้แบบละเอียด"   -> Jev : งานยาก ส่งโมเดลที่เก่งกว่า

[ Jev ยืนได้ทั้งหน้าและหลัง LLM ]
  หน้า  = Routing   : ตัดสินก่อนว่าส่งงานให้ใคร
  หลัง  = Guardrail : ตรวจ tool call ที่ Agent จะทำ ว่าเสี่ยงไหม แล้วบล็อกก่อนรันจริง

=> แนวคิดที่เอาไปใช้ต่อได้ : "อย่าใช้สมองใหญ่คิดทุกเรื่อง ใช้เฉพาะตอนที่จำเป็น"

--------------------------------------------------------------------------------
[ Jev ทำอะไรไม่ได้ ]
- แชท / เขียนโค้ด / เขียนงานสร้างสรรค์ / อธิบายเหตุผลเป็นตัวหนังสือ
- ตอบคำถามที่เราไม่ได้เตรียมตัวเลือกไว้ล่วงหน้า
=> มันไม่ได้มาแทน LLM และไม่ได้เก่งกว่า Agentic AI -- มันเป็นคนละแกนกัน
