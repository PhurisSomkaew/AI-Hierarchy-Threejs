# Handoff: หอคอย AI (AI Tower) สื่อการเรียนรู้ 3D แบบเดินสำรวจ

## Overview
สื่อการสอนแบบเล่นได้ อธิบาย **ลำดับขั้นของ AI 4 ชั้น** (AI → Machine Learning → Deep Learning →
Generative AI) ผู้เล่นเดินสำรวจหอคอย 4 ชั้นในมุมมองบุคคลที่สาม แต่ละชั้นมี **กระดานเรียนรู้**
(เนื้อหาจาก docs ของผู้สอน), **หุ่นยนต์ไกด์** ที่เล่าเรื่องและสั่งภารกิจ, **มินิเกม** ที่ต้องลงมือทำเอง,
และ **การ์ดสรุปศัพท์** ตอนจบชั้น

กลุ่มเป้าหมายคือคนทั่วไปที่ไม่มีพื้นฐาน AI ใช้บรรยายสดผ่านโปรเจกเตอร์และให้เล่นเองบนคอม

## ที่มาของโปรเจกต์ ก่อนจะมาเป็นหอคอย

หอคอยนี้ไม่ได้เริ่มจากศูนย์ ก่อนหน้านี้มันคือ **scroll page หน้าเดียว** (`index.html` ที่ยังเก็บไว้ใน
โฟลเดอร์นี้) ซึ่งเป็นตัวที่ตกผลึกเรื่อง **เนื้อหาและวิธีเล่าเรื่อง** มาแล้ว ก่อนจะถูกยกเครื่องฝั่งหน้าบ้าน
เป็นเกม 3D แบบเดินสำรวจ

ส่วนนี้บันทึกไว้เพื่อให้คนที่ทำต่อรู้ว่า **ทำไมเนื้อหาถึงถูกจัดแบบนี้** หลายอย่างเป็นผลจากการลองผิด
ลองถูกมาแล้ว ไม่ใช่การจัดเรียงตามใจ

### 3. Concept ที่ตกผลึกมาแล้ว (ส่วนนี้สำคัญกว่าโค้ด)

ห้าข้อนี้เป็นผลจากการแก้ซ้ำหลายรอบ ถ้าทำต่อแล้วเผลอทำหลุดข้อใดข้อหนึ่ง งานจะถอยหลังทันที

**a. กลุ่มเป้าหมายคือคนทั่วไปในบริษัท ไม่ใช่คนสายงานนี้**
ห้ามเปิดด้วยศัพท์ เพราะคนทั่วไปไม่รู้จักคำว่า "Rule-Based" ตั้งแต่แรก ศัพท์ทุกคำต้องมีคำอธิบาย
กำกับตอนโผล่ครั้งแรก

**b. แกนของเรื่องคือ "วิวัฒนาการ" ไม่ใช่ "การจัดหมวดหมู่"**
เวอร์ชันแรกเล่าเป็นการ์ด 4 ใบเรียงกัน ซึ่งอ่านแล้วเหมือนของ 4 อย่างที่แยกกันอยู่ ทั้งที่ไม่ควรเป็นแบบนั้น
ตัวที่ใช้จริงคือเล่าว่า **แต่ละชั้นเพิ่มอะไรเข้ามา**:

```
AI                              กฎที่คนเขียนไว้ให้
AI  + เรียนรู้จากข้อมูลใหม่เองได้         = ML
ML  + Neural Network ที่หาลักษณะเอง   = DL
DL  + Generator Model ที่สร้างของใหม่ได้ = GenAI
```

และ **เหตุผลที่ต้องเพิ่มของชิ้นนั้น = ปัญหาของชั้นก่อนหน้า** ซึ่งมีอยู่ใน docs อยู่แล้ว ไม่ได้แต่งขึ้น
เช่น `agentic.txt` เขียนตรง ๆ ว่า DL เกิดขึ้นเพราะ *"มนุษย์ไม่สามารถระบุให้กับข้อมูล Group นั้นได้ว่ามี
Feature อะไรบ้าง ? มี Pattern อะไรบ้าง ?"*

| ชั้น | ปัญหาที่เจอ | ทางแก้ |
|---|---|---|
| AI | กฎตายตัว ข้อมูลใหม่มาทีคนต้องมาแก้กฎเองทุกครั้ง | → ML |
| ML | ยังต้องให้คน Label ว่าแต่ละกลุ่มคืออะไร แต่บางทีคนก็บอกไม่ได้ | → DL |
| DL | เก่งเรื่อง "ตัดสินของที่มีอยู่" แล้ว แต่ยังสร้างของใหม่ไม่ได้ | → GenAI |
| GenAI | — | ต่อยอดเป็น LLM |

**c. ภาษาคนทั่วไปมาก่อน ศัพท์มาทีหลัง**
ทุกชั้นเปิดด้วยประโยคเดียวแบบภาษาชาวบ้านก่อนเสมอ เช่น DL เปิดด้วย *"ถ้าคนบอกไม่ได้ว่าข้อมูลกลุ่มนั้น
มีลักษณะอะไร — ก็ให้เครื่องหาเอง"* แล้วค่อยลง Supervised / Unsupervised / Backpropagation

**d. อะไรอยู่ Part ไหน ต้องอยู่ใน Part นั้น**
เวอร์ชันกลางเอา Neural Network, LLM, และศัพท์จำเป็น ไปกองเป็น "บทเสริม" ท้ายหน้า ผลคือคนอ่านจบ
4 ชั้นแล้วก็เลิกอ่าน ไม่มีใครลงไปถึง ตัวที่ใช้จริงคือยัดกลับเข้า Part ที่มันสังกัด:

- Neural Network → **Part 03 (DL)** เพราะ DL คือชั้นที่ Neural Network ถูกเพิ่มเข้ามา
- LLM / Transformer / ศัพท์ 4 ด่าน → **Part 04 (GenAI)** เพราะ LLM คือ GenAI ชนิดหนึ่ง

ของที่คาบเกี่ยวสองชั้น (Supervised / Unsupervised Learning ถูกสอนที่ DL แต่ถูกอ้างอีกทีตอนอธิบาย
Pretrain Model / Instruct Model) **ใช้ลิงก์ย้อนกลับ ไม่สอนซ้ำสองที่**

**e. ต้องรู้ตลอดเวลาว่าตัวเองอยู่ตรงไหน**
มีแถบ Part แบบ sticky ค้างบนสุด + แถบนำทางด้านขวาที่โชว์ป้ายชื่อตลอด (ไม่ใช่จุดเปล่า ๆ ที่ต้อง hover)

## About the Design Files
ไฟล์ในชุดนี้เป็น **design reference ที่เขียนด้วย HTML + three.js** เป็นต้นแบบที่แสดงหน้าตาและ
พฤติกรรมที่ต้องการ ไม่ใช่ production code ที่ควรก๊อปไปใช้ตรง ๆ

งานคือ **สร้างงานนี้ขึ้นใหม่ใน environment ของ codebase ปลายทาง** (React + react-three-fiber,
Vue + TresJS, Svelte, หรือ vanilla three.js ก็ได้) โดยใช้ pattern และ library ที่โปรเจกต์นั้นมีอยู่แล้ว
ถ้ายังไม่มี codebase ให้เลือก framework ที่เหมาะสมที่สุดแล้วสร้างตามนี้

> **แนะนำ:** ถ้าจะทำต่อในเว็บ ให้ใช้ **React + @react-three/fiber + @react-three/drei**
> โครงสร้างฉากในต้นแบบแมปเป็น declarative components ได้ตรง ๆ และแยกไฟล์ต่อชั้นได้สะอาดกว่า
> ไฟล์เดียว 2,100 บรรทัดแบบตอนนี้

## Fidelity
**High-fidelity (hifi)**: สี ฟอนต์ ระยะห่าง ขนาดตัวอักษร และ interaction ทั้งหมดเป็นค่าจริงที่ตั้งใจแล้ว
ผ่านการตรวจ contrast (WCAG AA 4.5:1) และขนาดปุ่มขั้นต่ำแล้ว ให้ทำตามค่าที่ระบุ

ข้อยกเว้น: โมเดล 3D ทั้งหมดสร้างจาก primitive ของ three.js (Box, Cylinder, Sphere, Capsule, Torus)
ไม่มีไฟล์โมเดลภายนอก ถ้าปลายทางมี asset pipeline สำหรับ .glb สามารถเปลี่ยนไปใช้โมเดลจริงได้

### จุดที่ต้องระวังตอน implement (เจอมาแล้วทั้งหมด)
1. **Keyboard focus**: ต้องใส่ `tabindex="0"` บน canvas และ `focus()` ตอนโหลด + ทุกครั้งที่คลิก
   ไม่งั้นปุ่มที่กดจะไม่ถึงตัวเกมเลย และต้องดักทั้ง `window` และ `document`
2. **ปุ่มค้าง**: ต้อง `keys.clear()` เมื่อเปิด modal, เมื่อ blur, และเมื่อ `visibilitychange`
   ไม่งั้นตัวละครจะเดินค้างไปทางเดียว
3. **Canvas sizing**: ห้ามให้ three.js เขียน inline style ลง canvas (`setSize(w, h, false)`)
   ให้ CSS เป็นเจ้าของกล่อง ถ้า three.js เขียน inline width ที่วัดพลาดครั้งเดียว จอจะดำถาวร
4. **แผง modal บนจอเตี้ย**: หัวข้อกับปุ่มต้อง `flex:none` และให้เฉพาะเนื้อหาตรงกลาง scroll
   (`flex:1 1 auto; min-height:0; overflow:auto`) ไม่งั้นปุ่มตกจอบนโปรเจกเตอร์ 540px
5. **Event delegation**: ปุ่มในรายการที่สร้างด้วย `innerHTML` ควร bind ที่ container ไม่ใช่รายตัว

### Flow ของแต่ละชั้น (state machine)
```
lobby → toLift → f{N}intro → f{N}quest → f{N}wrap → f{N}done
```
- เข้าชั้นครั้งแรก → `intro` (ต้องอ่านกระดาน + คุยไกด์ก่อนถึงเปิดเกมได้)
- คุยไกด์จบ → `quest` (เล่นเกมได้)
- เล่นผ่านเงื่อนไข → `wrap` (ไกด์ขึ้นเครื่องหมาย `!` ให้กลับไปคุย)
- คุยรอบสอง → `done` + การ์ดสรุป
- **ทุกชั้นเข้าได้ทุกลำดับ** ไม่ต้องเรียง และจำสถานะแต่ละชั้นแยกกัน (`visited` / `cleared` Set)

### รายละเอียดเกมแต่ละชั้น
**ชั้น 1 · ตู้กดน้ำ**: เงื่อนไข 2 ข้อ (เหรียญ 10 → จ่ายน้ำ, เหรียญ 5 → รออีก 5)
ผู้เล่นหย่อนของ 5 ชนิด ต้องลองทั้งของที่ตรงเงื่อนไข 1 ครั้ง และไม่ตรง 1 ครั้ง
ของที่ไม่ตรง → ตู้สั่น + จอขึ้น ERROR (สอนว่า Rule-Based เจอของนอกกฎแล้วไปต่อไม่ได้)

**ชั้น 2 · คัดผลไม้**: ผู้เล่นลากเส้นแบ่ง 2 กลุ่มบน canvas 2D
กด "ปล่อยล็อตใหม่" → ข้อมูลใหม่ทำให้เส้นเดิมแม่นลดลง
กด "ให้เครื่องปรับเส้นเอง" → เส้นขยับเอง (สอนว่า ML อัปเดตกฎตัวเองได้)

**ชั้น 3 · Weight**: ปุ่ม +/− 4 ตัวปรับ Weight ให้ผลลัพธ์ที่ต้องการชนะเกิน 70%
แล้วกด "ให้เครื่องเรียนเอง" → gradient descent ทำงาน + คลื่นสีแดงไหลย้อนกลับ (Backpropagation)

**ชั้น 4 · Generator**: เลือกวิธีปั้น 3 จุด (ลายเส้น/โทนสี/ลายน้ำ) ส่งให้ Discriminator ตรวจ
**ทุกครั้งที่หลอกผ่าน ตัวตรวจจะเพิ่มจุดตรวจอีก 1 จุด** (1→2→3) ต้องผ่าน 3 รอบ

## State Management
```js
mode      // 'walk' | 'talk' | 'items' | 'docs' | 'rules' | 'ml' | 'dl' | 'ga' | 'lift' | 'ride' | 'card'
level     // 0 = โถง, 1-4 = ชั้น
stage     // state machine ข้างบน
visited   // Set<number> ชั้นที่เคยเข้า
cleared   // Set<number> ชั้นที่เล่นจบ
look      // { yaw, pitch, dist } มุมกล้องที่ผู้เล่นปรับเอง
keys      // Set<string> ปุ่มที่กดค้างอยู่
```
เกมแต่ละชั้นมี state ของตัวเอง: `fedOk/fedBad/half` (ช 1), `mlLine/mlAcc/mlPhase` (ช 2),
`DLW[4]/dlPhase` (ช 3), `gaPick/gaLevel/gaPasses/gaVerdict` (ช 4)

ไม่มี data fetching ทุกอย่างอยู่ในไฟล์ ไม่ต้องต่อ API

## วิธีเปิดดูต้นแบบ

**หอคอย (`tower.html`)** ใช้ ES modules จึงต้องเสิร์ฟผ่าน http เปิดไฟล์ตรง ๆ จะค้างอยู่ที่
"กำลังสร้างหอคอย…" เพราะเบราว์เซอร์บล็อก module import จาก `file://`

```bash
cd ai-hierarchy-web
python3 -m http.server 8000
# เปิด http://localhost:8000/tower.html
```

**scroll page (`index.html`)** เป็นไฟล์เดียวจบ ไม่ใช้ module ดับเบิลคลิกเปิดได้เลย
หรือเปิดผ่าน server เดียวกันที่ http://localhost:8000/ ก็ได้
